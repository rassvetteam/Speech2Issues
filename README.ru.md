# Speech2Issues

<p align="center">
  <a href="README.md"><strong>English</strong></a> · <a href="README.ru.md"><strong>Русский</strong></a>
</p>

Windows-приложение, которое одной кнопкой записывает микрофон и звук ПК, сводит их в один mono WAV, локально распознаёт речь через Whisper, передаёт готовый текст выбранному ИИ-провайдеру и создаёт задачи в PLANKA, GitHub Issues, Obsidian и webhook.

## Требования

- Windows 10/11;
- .NET 8 SDK;
- один доступный ИИ-провайдер: Ollama, LM Studio или OpenAI-compatible API;
- хотя бы одна установленная/доступная completion-модель выбранного провайдера;
- для GitHub — авторизованный GitHub CLI (`gh auth login`) либо fine-grained PAT с правом Issues: write.

Распознавание работает полностью локально через [Whisper.net](https://github.com/sandrohanea/whisper.net). При первом запуске специальный мастер предлагает CPU/CUDA runtime, модель Whisper и провайдера ИИ. По умолчанию выбрана качественная мультиязычная `LargeV3Turbo` (около 1,6 ГБ). Runtime и модель скачиваются атомарно в `%LocalAppData%\Speech2Issues`; на NVIDIA предлагается CUDA с автоматическим откатом на CPU.

Примеры локальных адресов:

```powershell
Invoke-RestMethod http://127.0.0.1:11434/api/version
ollama list
Invoke-RestMethod http://127.0.0.1:1234/v1/models
```

## Запуск

```powershell
dotnet restore Speech2Issues.sln
dotnet run --project src/Speech2Issues.App
```

1. При первом запуске дождитесь загрузки Whisper и выберите Ollama, LM Studio либо OpenAI-compatible API. Мастер завершится только после реального проверочного ответа модели.
2. В «Настройки → Аудио и клавиша» выберите микрофон, устройство воспроизведения и проверьте Whisper. Там же задаётся, сколько минут держать загруженную модель в памяти после распознавания: `0` выгружает её сразу, по умолчанию — 5 минут.
3. В «Настройки → Подключения» добавьте общие учётные данные платформ.
4. Создайте локальный проект или импортируйте найденный проект из PLANKA, GitHub либо Obsidian.
5. В настройках проекта включите одно или несколько назначений. Для PLANKA разрешите нужные списки и выберите резервный.
6. Выберите рабочий проект и нажмите микрофон. После обработки есть 5 секунд для отмены, редактирования или немедленной отправки.

Whisper получает весь mono WAV 16 кГц и возвращает транскрипт на исходном языке. Только после этого выбранная completion-модель получает текст и создаёт проверяемый структурированный JSON. Аудио ИИ-провайдеру не отправляется.

## Провайдеры ИИ

- **Ollama** — нативные `/api/tags`, `/api/show` и `/api/chat`.
- **LM Studio** — OpenAI-compatible API, по умолчанию `http://127.0.0.1:1234/v1`; Bearer-токен необязателен.
- **OpenAI-compatible API** — произвольный HTTP/HTTPS Base URL, ID модели и необязательный Bearer-токен.

Токен хранится только в `secrets.bin`, зашифрованном Windows DPAPI. Для серверов без `/models` ID модели можно ввести вручную.

## Проекты и маршрутизация

- При обычном запуске приложение показывает выбор рабочего проекта; последний использованный проект выделен.
- Подключения и секреты платформ общие, но репозитории, папки, PLANKA-списки и набор назначений хранятся отдельно в каждом проекте.
- Один проект может отправлять задачу сразу в несколько платформ.
- Для PLANKA модель выбирает список только из разрешённого набора. Неизвестный ID заменяется резервным списком, а в редакторе выбор можно изменить вручную.
- Частичный успех сохраняется: повтор из истории отправляет только назначения с ошибкой.

## Трей и горячая клавиша

- Закрытие окна сворачивает приложение в трей (не завершает его) — запись можно запускать, пока окно скрыто.
- В «Настройки → Горячая клавиша записи» задаётся глобальное сочетание для старта/остановки записи. По умолчанию — `Ctrl+F9`.
- В трее доступны: «Начать/Остановить запись», «Открыть окно», «Настройки» и «Выход».
- Флаг «Запускать свёрнутым в трей (автономный режим)» прячет окно при старте — приложение живёт только в трее и управляется горячей клавишей.

## Назначения

- **PLANKA 2.1.1** — карточка в выбранном ИИ или вручную разрешённом списке.
- **GitHub Issues** — отдельный `owner/repo` для каждого проекта, только существующие labels.
- **Obsidian Project Manager** — полный `pm-task` frontmatter и обновление `taskIds` проекта.
- **Obsidian TaskNotes** — отдельная Markdown-задача с YAML.
- **Obsidian Tasks** — checkbox в Inbox и ссылка на подробную заметку.
- **Obsidian Markdown** — обычная отдельная заметка.
- **Webhook** — `POST` объекта `{ schemaVersion: 1, source, task }` с заголовком `Idempotency-Key`.

Каждая задача содержит скрытый маркер `speech2issues:<id>`. Повторная отправка сначала ищет этот маркер и не создаёт дубль.

## Данные и приватность

Данные находятся в `%LocalAppData%\Speech2Issues`:

- `settings.json` — несекретные настройки;
- `secrets.bin` — API keys и tokens, зашифрованные Windows DPAPI для текущего пользователя;
- `history.db` — транскрипты, статусы и ссылки;
- `models\` — локальные GGML-модели Whisper;
- `runtime\` — скачанные CPU/CUDA библиотеки Whisper только для Windows x64;
- `components.json` — версия и состав установленных компонентов;
- `recordings\` — временный WAV до успешной отправки; при отмене или ошибке он остаётся для повтора и может быть удалён кнопкой в истории.

После успешного создания WAV удаляется. Секреты и аудио не записываются в логи.

## Сборка готового exe

```powershell
.\build.ps1
```

Скрипт восстанавливает пакеты, прогоняет обычные тесты и публикует самодостаточный
single-file exe в `publish\Speech2Issues.exe` (Windows x64, .NET встроен —
устанавливать рантайм не нужно). Сборка завершается ошибкой, если EXE превышает
100 МБ или в публикацию случайно попали Whisper runtime-пакеты. Ручной вариант:

```powershell
dotnet publish src/Speech2Issues.App -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:IncludeAllContentForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish
```

## Тесты

```powershell
dotnet test Speech2Issues.sln
```

Обычные тесты не создают внешних задач. Live-тесты отдельно проверяют локальный Whisper на контрольном WAV и текстовую генерацию задачи установленной Ollama-моделью:

```powershell
dotnet test tests/Speech2Issues.Tests --filter Category=Live
```

Whisper live-тест использует маленькую модель `Tiny`, временно скачивает её и проверяет ожидаемую фразу. Основное приложение по умолчанию использует `LargeV3Turbo`.

Отдельно проверить реальный захват WASAPI без обращения к Ollama и без создания задач:

```powershell
dotnet run --project tools/Speech2Issues.AudioSmoke -- 3
```

Распознать сохранённый mono WAV без обращения к ИИ и без создания внешней задачи:

```powershell
dotnet run --project tools/Speech2Issues.AudioSmoke -- --transcribe "C:\path\recording.wav" LargeV3Turbo
```
